# Нагрузочное тестирование T-RESERVE

## Инструмент: k6

### Установка k6

**Windows (Chocolatey):**
```bash
choco install k6
```

**Windows (прямая установка):**  
Скачать с https://github.com/grafana/k6/releases и добавить в PATH

---

## Запуск тестов

### 1. Поднять всё окружение
```bash
docker compose -f docker-compose.prod.yml up --build -d
```

### 2. Запустить нагрузочный тест
```bash
k6 run load-tests/k6-load-test.js
```

### 3. Запустить с кастомным базовым URL (например, продакшен)
```bash
k6 run -e BASE_URL=http://your-server load-tests/k6-load-test.js
```

## Что тестируем

В тесте 4 возможных сценария (управляются переменной `SCENARIO`):

### 1. `mixed` (по умолчанию, если `SCENARIO=all` или `mixed`)
Имитация реального трафика (пользователи заходят, смотрят ивенты, открывают случайные места и пытаются забронировать).
Используется **ramping-vus**: плавный разгон и спад количества виртуальных пользователей (от 0 до 100).
- Цель: проверить, как система справляется с реалистичным смешанным трафиком.

### 2. `race` (`SCENARIO=race`)
Гонка данных (Race condition): **1000 VU (виртуальных юзеров) одновременно бьют в одно и то же место**.
- Цель: Проверка распределённых блокировок (Redis Distributed Lock). Ровно 1 победитель (200 OK) и 999 отлупов (409 Conflict).

### 3. `sustained` (`SCENARIO=sustained`)
Постоянная стабильная нагрузка: **constant-arrival-rate**, скрипт старается держать ровно 300 RPS (запросов в секунду) на протяжении 30 секунд.
- Цель: Проверить, как система (RabbitMQ, Postgres Connection Pool, GC) ведёт себя под постоянной, стабильной высокой нагрузкой (без всплесков), нет ли утечек или деградации от длительности.

### 4. `redis_stress` (`SCENARIO=redis_stress`)
Стресс-тест Redis: **ramping-arrival-rate**, разгоняет генерацию запросов на лок с 100 RPS до **5000 RPS**. В этом тесте мы бьём по рандомным билетам (не одному), чтобы исключить lock-конфликт в Postgres и нагружать чисто пропускную способность Redis SETNX.
- Цель: Найти потолок (предел деградации), при котором Redis перестает отвечать за 2 мс и начинает выдавать connection refused или latency > 50ms.
